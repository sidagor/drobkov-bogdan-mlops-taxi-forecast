# Model Card (Карточка модели) — Автоматизированный MLOps-пайплайн прогнозирования заказов такси

## 1. Model Details (Информация о модели)

| Параметр | Описание |
|---|---|
| Название проекта | Taxi Orders Forecasting |
| Тип решения | MLOps-пайплайн машинного обучения |
| Задача | Прогнозирование временного ряда |
| Тип ML-задачи | Регрессия |
| Целевая переменная | `num_orders` |
| Используемые алгоритмы | LinearRegression, RandomForestRegressor, CatBoostRegressor |
| Критерий выбора модели | RMSE |
| Лучшая модель текущего эксперимента | LinearRegression |
| Лучший результат текущего эксперимента | RMSE = 34 |
| Основные инструменты | Python, pandas, scikit-learn, CatBoost, MLflow, Docker, pytest |
| Репозиторий | https://github.com/sidagor/drobkov-bogdan-mlops-taxi-forecast/tree/feature/production-standards |

Проект представляет собой автоматизированный процесс подготовки данных, обучения нескольких моделей машинного обучения, сравнения их качества и выбора наиболее подходящей модели для решения задачи прогнозирования.

## 2. Intended Use (Назначение и применение)

Основное назначение проекта — прогнозирование количества заказов такси в аэропортах на следующий час.

Решение предназначено для помощи в планировании распределения водителей с учётом ожидаемого спроса.

MLOps-пайплайн автоматизирует основные этапы работы с моделями:

- подготовку и обработку исходных данных;
- формирование признаков для обучения;
- обучение нескольких алгоритмов;
- подбор гиперпараметров;
- сравнение качества моделей;
- выбор лучшей модели по метрике RMSE;
- сохранение результатов обучения и оценку модели.

Пайплайн может использоваться для повторного обучения моделей при поступлении обновлённых данных.

## 3. Training Data and Evaluation Data (Данные для обучения и оценки)

Для обучения используется набор данных с историческими сведениями о количестве заказов такси.

Исходные данные находятся в файле `data/raw/taxi.csv`.

Целевая переменная — `num_orders`, отражающая количество заказов за определённый временной интервал.

Перед обучением данные агрегируются по часам. Для этого используется ресемплирование с интервалом в один час и суммированием количества заказов.

Далее формируются дополнительные признаки:

| Признак | Описание |
|---|---|
| `dayofweek` | День недели |
| `hour_*` | Час суток, представленный набором One-Hot признаков |
| `lag_1` | Количество заказов за предыдущий час |
| `lag_23` | Количество заказов 23 часа назад |
| `lag_24` | Количество заказов 24 часа назад |
| `lag_48` | Количество заказов 48 часов назад |
| `lag_72` | Количество заказов 72 часа назад |
| `lag_168` | Количество заказов 168 часов назад |
| `rolling_mean` | Среднее количество заказов за предыдущие 24 часа |

Разделение данных выполняется без перемешивания, чтобы сохранить временную последовательность наблюдений:

- 90% данных используются для обучения;
- 10% данных используются для тестирования.

Такой подход позволяет учитывать временную структуру задачи и не перемешивать прошлые и будущие наблюдения.

## 4. Training and Model Selection (Обучение и выбор модели)

В проекте реализован автоматизированный процесс обучения и сравнения трёх алгоритмов:

1. **LinearRegression** — линейная регрессия.
2. **RandomForestRegressor** — ансамбль решающих деревьев, использующий метод случайного леса.
3. **CatBoostRegressor** — градиентный бустинг над деревьями решений.

Для подбора гиперпараметров используется `GridSearchCV`.

После обучения модели сравниваются по метрике RMSE. Алгоритм с наименьшим значением RMSE считается наиболее подходящим для решения поставленной задачи.

По результатам текущего эксперимента лучшей оказалась модель `LinearRegression` с RMSE = 34.

Обучение и логирование результатов выполняются с использованием MLflow. Обученная модель сохраняется в директории `models/`.

## 5. Input and Output (Входные и выходные данные)

**Входные данные**

На вход пайплайна поступают исторические данные о количестве заказов такси.

Для работы модели используются следующие группы признаков:

- временные признаки: день недели и час суток;
- лаговые признаки: значения количества заказов за предыдущие часы и дни;
- скользящее среднее за предыдущие 24 часа.

**Выходные данные**

Результатом работы модели является прогноз количества заказов такси на следующий час.

Выходное значение представляет собой числовую оценку количества заказов.

## 6. Metrics (Метрики качества)

Для оценки качества моделей используется метрика RMSE (Root Mean Squared Error) — корень из среднеквадратичной ошибки.

Она позволяет оценить отклонение прогнозируемых значений от фактических с повышенным штрафом за большие ошибки.

Формула метрики:

$$
RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}
$$

где:

- $n$ — количество наблюдений;
- $y_i$ — фактическое количество заказов;
- $\hat{y}_i$ — предсказанное количество заказов.

Чем ниже значение RMSE, тем точнее прогноз модели.

## 7. Quantitative Analysis (Количественный анализ)

В проекте сравниваются три алгоритма машинного обучения. Выбор осуществляется на основании значения RMSE.

| Модель | RMSE |
|---|---:|
| LinearRegression | **34** |
| CatBoostRegressor | 40 |
| RandomForestRegressor | 42 |

По результатам эксперимента минимальное значение ошибки показала LinearRegression. Она была выбрана пайплайном в качестве лучшей модели.

Результаты показывают, что более сложные алгоритмы не обязательно обеспечивают более высокое качество на конкретном наборе данных. В данном случае линейная регрессия превзошла CatBoostRegressor и RandomForestRegressor по выбранной метрике.

## 8. Factors (Факторы, влияющие на качество)

На качество прогнозирования могут влиять следующие факторы:

- **Суточная сезонность.** Количество заказов может существенно различаться в зависимости от времени суток.
- **Недельная сезонность.** Спрос может зависеть от дня недели.
- **Исторические значения.** Количество заказов в предыдущие часы и дни может быть связано с текущим спросом.
- **Изменение характера спроса.** Со временем распределение заказов может меняться, что способно снизить качество прогнозов.
- **Качество исходных данных.** Пропуски, ошибки и некорректные значения могут отрицательно повлиять на обучение.

Для учёта временных закономерностей в проекте используются календарные признаки, лаги и скользящее среднее.

## 9. Ethical Considerations (Этические аспекты)

Прогнозирование количества заказов такси не предполагает непосредственной обработки персональных данных пассажиров в рамках описанной задачи.

При этом результаты модели следует рассматривать как оценку будущего спроса, а не как гарантированное значение количества заказов.

Ошибки прогнозирования могут привести к неоптимальному распределению водителей: недостаточному количеству машин в периоды высокого спроса или избыточному количеству машин в периоды низкого спроса.

Поэтому при практическом использовании результатов необходимо учитывать возможные отклонения прогноза от фактического спроса.

## 10. Caveats and Recommendations (Ограничения и рекомендации)

Основные ограничения решения:

- модель обучается на исторических данных и может хуже работать при изменении характера спроса;
- прогнозирование зависит от наличия корректных исторических значений для формирования лаговых признаков;
- качество прогноза оценивается с помощью RMSE, поэтому отдельные большие ошибки могут существенно влиять на итоговую метрику;
- полученные значения RMSE относятся к текущему эксперименту и не гарантируют аналогичного качества на новых данных;
- в проекте реализованы обучение, сравнение и сохранение моделей, но наличие отдельного сервиса для обработки прогнозных запросов в реальном времени не предполагается.

**Рекомендации по дальнейшему развитию:**

- регулярно переобучать модели на обновлённых данных;
- отслеживать изменение качества прогнозирования;
- расширять набор признаков при наличии обоснования и полезных данных;
- сохранять историю экспериментов и результатов в MLflow;
- при дальнейшем развитии проекта реализовать отдельный сервис для получения прогнозов.

Таким образом, проект представляет собой MLOps-пайплайн, автоматизирующий процесс обучения и выбора модели машинного обучения для прогнозирования спроса на такси.
